# 面试时间线与低延迟回答实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立三角色本地面试时间线、自动 Markdown 记录、简历参与回答和低延迟流式口语答案。

**Architecture:** 新增独立 `interviewhistory` 包负责 SQLite、异步写入和 Markdown 投影；`interview.Manager` 仍负责实时会话，但通过明确的 Recorder 接口记录最终事件。前端只消费统一时间线，实时 partial 和 AI chunk 更新同一条消息，历史通过 Wails API 从本机恢复。

**Tech Stack:** Go 1.24、Wails 2、SQLite FTS5/go-sqlite3、Vue 3、Pinia、Vitest、Windows Poppler/Tesseract。

## Global Constraints

- 所有命令通过 `C:\Program Files\PowerShell\7\pwsh.exe -NoLogo -NoProfile -Command` 执行。
- 本机数据默认保存到当前 Windows 用户目录，不上传面试记录。
- 不改动 F7、F9、F10、窗口置顶、鼠标穿透和共享画面隔离语义。
- 面试官问题、AI 参考答案和求职者实际回答必须使用同一时间线。
- 明确句尾后的目标确认时间为 450–800ms。
- SQLite、Markdown 和复盘写入不进入首答串行链路。
- 当前目录不是 Git 仓库；每个阶段用测试输出、生产构建哈希和 `变更记录.md` 代替 commit。

- [ ] **Step 3: 实现 SQLite schema 和幂等 upsert**

```go
type Role string
const (
	RoleInterviewer Role = "interviewer"
	RoleAISuggestion Role = "ai_suggestion"
	RoleCandidate Role = "candidate"
)

type Message struct {
	ID, SessionID, TurnID, QuestionID string
	Role Role
	Content string
	Status MessageStatus
	CreatedAt, UpdatedAt time.Time
}
```

数据库建立 `interview_sessions` 和 `interview_messages`；消息以 `id` 为主键，`ON CONFLICT(id) DO UPDATE` 更新正文和状态，查询按 `created_at, id` 排序，空结果返回 `[]`。
