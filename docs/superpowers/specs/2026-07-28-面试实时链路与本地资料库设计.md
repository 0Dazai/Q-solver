# 面试实时链路与本地资料库设计

## 目标

在保留 Go、Wails、Vue 3 技术栈的前提下，使 Q-Solver 能够：

1. 通过 Windows WASAPI Loopback 持续采集腾讯会议等软件播放的对方语音。
2. 在本机显示窗口的同时，通过现有 F9 语义启用 Windows 屏幕捕获隔离。
3. 低延迟完成转写、问题聚合、资料检索和流式回答。
4. 导入本机 Markdown 资料，默认使用本地 SQLite FTS5 检索。
5. 允许配置可选云端向量检索；云端异常时继续使用本地结果。
6. 支持“通用回答、资料优先、仅限资料”三种回答模式，并展示引用来源。

## 边界

- 第一阶段正式支持 Markdown；PDF 保留统一文档解析接口，后续接入。
- 原始资料、SQLite 索引和检索元数据保存在本机。
- 云端向量功能默认关闭，不是回答链路的必需依赖。
- 只把当前问题命中的少量资料片段发送给回答模型。
- 普通最小化、窗口收起、鼠标穿透和屏幕捕获隔离保持独立语义。
- 不改写或移动用户原始资料。

## 架构

### 实时面试

`SessionController` 负责会话生命周期和 SessionID；`AudioSupervisor` 负责系统音频与麦克风采集；`TranscriptionSupervisor` 负责 ASR 发送、接收和重连；`TurnCoordinator` 负责问题聚合、去重和提交；`AnswerCoordinator` 负责检索、回答抢占、队列和流式输出；`StatePublisher` 负责带会话版本的前端事件。

### 资料库

Markdown 解析器输出带文件、标题路径和内容哈希的片段。SQLite 存储文档、片段和 FTS5 索引。本地检索始终执行；可选语义检索器返回额外候选，融合器按关键词、标题、专有名词和语义分数去重排序。

### 前端

面试工作区采用三栏信息架构：左侧转写和监听状态，中间当前问题和操作，右侧回答和资料引用。窄窗口切换为单列并折叠转写与引用。后端状态是权威来源，前端按 SessionID 和事件序号丢弃旧事件。

## 并发与故障策略

- ASR Client 由 Supervisor 持有；发送循环遇到可恢复错误后等待 Client 代次更新，不永久退出。
- 每次 Start 生成新的 SessionID；旧会话事件不进入当前前端状态。
- 最新问题优先：新问题到来时取消旧回答，保留已生成文本并开始最新问题。
- 待处理问题上限为 3，重复问题按指纹合并。
- 系统 ASR 与本机 ASR 独立重连；本机 ASR 失败不停止系统音频监听。
- 云向量检索失败、超时或未配置时直接返回本地 FTS 结果。

## 屏幕捕获隔离

继续使用 Windows `SetWindowDisplayAffinity`，F9 只控制捕获隔离。状态需区分启用、关闭、不支持和调用失败。普通最小化继续使用系统最小化，不使用窗口隐藏替代。

- 前端：为 store 和事件过滤增加测试运行入口，并执行生产构建。
